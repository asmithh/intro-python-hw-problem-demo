### Problem Statement:
Write a program that, given a non-negative integer `year`, calculates `days_elapsed`, the number of days that have elapsed between January 1 of `year` and January 1, 1970. Then calculate `whole_weeks`, the number of whole weeks elapsed between `year` and January 1, 1970. Remember that leap years happen every 4 years, and leap days occur on February 29. We'll assume `year` is always greater than or equal to 1970.

A synodic month is one way of defining the lunar month (the time between two consecutive new moons or full moons; definitions vary across the wide array of lunar calendars different cultures and religions have invented). The synodic month is 29.53 days. Write code to calculate `full_moons`, which is the number of full moons that occurred between January 1 of 1970 and January 1 of `year`. The first full moon of 1970 occurred on January 22, 1970.

Please put your code in a file called `time_elapsed.py`. 

### Rationale:
This question is meant to assess a learner's ability to apply their knowledge of floor division in a novel context and introduce them to off by one errors. Datetime calculations are notoriously annoying to do by hand (which is why we have extensive Python modules that do this for us), but it's nice to have some intuition for the ways that floor division is involved in these computations. Datetime math comes up very frequently in a variety of fields. I most often see it in the context of timestamps for events on social media platforms, like follow events or reposts. Here, I'm posing a problem that not only requires users to count periodic events using floor division (which is an interesting inversion of the idea that modulo is what we use to deal with periodic phenomena) but also requires some very careful consideration around the way events are counted. This offers a useful introduction to the off by one error, which is exactly what it sounds like: sometimes, when we write a program to count something, our count will be off by exactly one. Off by one errors often happen because we've started counting at the wrong point, we've counted something twice, or we've neglected to count an element (usually the first one). In this case, a naive solution may double count the last leap year (since leap years happen on February 29, if the variable `year` is a multiple of 4, we will not have experienced the leap day in `year` by January 1 of `year`).

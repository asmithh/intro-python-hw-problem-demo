### Problem Statement
Write an interactive "Rock, Paper, Scissors" game. Players should be able to enter their names and be addressed by their names. The script should let players play three rounds of "Rock, Paper, Scissors" and indicate who won each game, as well as the overall winner (if there is one). It should be able to detect tie conditions as well. 

### Rationale
This problem presents an opportunity to write *a lot* of conditionals to implement a familiar game; learners will also have to think carefully about the structure of their program and leverage their string formatting skills. It combines 3 classes' worth of material into one problem statement, asking learners to synthesize the skills they've been working on recently. One of the challenges will be figuring out how to set up the conditionals in a way that is compact and elegant -- there are more and less clunky ways to navigate the gameplay structure. Thinking about the combinatorics involved may be useful, but trial and error may also be a valid approach. Another challenge is that this requires learners to write a lot of code, because, as mentioned above, there are just a lot of conditionals to navigate! There is also an opportunity to write multiple functions and carefully consider what a meaningful chunk of code / computation looks like in this particular context.
